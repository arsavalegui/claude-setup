Construido 2026-08-28. Repo **arsavalegui/fhir-agent-poc** (privado), en `~/Projects/fhir-agent-poc`. Es el patrón de [[Framework Bot escala]]/lemut **generalizado a datos estructurados**.

## Qué es
Subes JSON crudo (FHIR salud, o cualquier otro) → se guarda en Postgres `jsonb` SIN aplanar (equivalente open-source al tipo `dynamic` de KQL) → agente text-to-SQL traduce preguntas en español a SELECT, ejecuta en solo-lectura y **devuelve la query para verificar**.

## Arquitectura (dockerizada, open source)
- **Postgres 16** jsonb + GIN. Tabla `resources(id,tipo,paciente_id,recurso jsonb)` + vista `resources_anon` (capa PII).
- **API FastAPI** (`api/`) puerto **8010** (8000 estaba ocupado). UI en `static/index.html`: preguntar, subir JSON, ver config.
- **Agente** (`api/agente.py`): LLM **100% LOCAL con Ollama** (`host.docker.internal:11434/v1`, modelo `qwen2.5-coder:3b`, ~1.9GB, CPU, ~11s/pregunta). Vars `LLM_URL`/`LLM_MODELO`. Se cambió de OmniRoute a Ollama porque el pool gratis se agotaba (429→403). Solo permite SELECT (validado), timeout 8s, rollback siempre.
- **Config partida** como pidió el usuario: `config/agente_general.md` (comportamiento general) + `config/fuentes/fhir/descripcion.md` (2a descripción fuente) + `reglas.md` (2b reglas). Para otro cliente/fuente solo cambian 2a y 2b.
- **PII**: vista `resources_anon` borra name/telecom/address/identifier/contact del Patient, birthDate→año. Producción: integrar **Microsoft Presidio** (open source MIT) para PII en texto libre. Falta.
- Datos: 8 pacientes sintéticos Synthea (FHIR R4), 2614 recursos en `datos_fhir/bundles/`.
